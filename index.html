A transactional SQL cache inside PostgreSQL

Keep using ordinary primary-key SELECT, or call SQL GET/MGET through the same PostgreSQL driver. Ordinary DML fences affected entries before commit visibility.

SQL only

Primary-key SELECT and SQL GET/MGET use the existing PostgreSQL connection and permissions.

Whole rows

Complete tuples keyed by the table primary key.

Transaction-aware invalidation

Source writes fence affected entries before commit visibility.

Bounded extension memory

Deterministic extension allocations are bounded at startup; host limits remain separate.

Current SQL MGET benchmark

PostgreSQL 16.14, 4,096 incompressible 3,000-byte rows, 16 connections, 32 keys per MGET, two seconds of warmup, and three rotated five-second repetitions.
