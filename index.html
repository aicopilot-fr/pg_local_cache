A transactional SQL KV cache inside PostgreSQL

Use GET and MGET through your PostgreSQL driver. Keep ordinary DML and fence affected entries before commit visibility.

SQL only

Primary-key SELECT uses the existing PostgreSQL connection and permissions.

Whole rows

Complete tuples keyed by the table primary key.

Transaction-aware invalidation

Source writes fence affected entries before commit visibility.

Bounded extension memory

Deterministic extension allocations are bounded at startup; host limits remain separate.

Reference SQL KV snapshot

PostgreSQL 16.14, 4,096 incompressible 3,000-byte values, 16 connections, batches of 32 key positions, and three rotated five-second repetitions.
